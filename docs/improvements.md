## 2. 新實作：多視窗集成

以不同滑動視窗保留不同長度的歷史，降低只選一種記憶長度的依賴。預先指定視窗，不使用標籤、未來資料或已知 drift 位置。這是研究候選方法，不能保證優於最佳單一視窗。

- `--windows 2048 4096 --trees 32`：各 16 棵樹，維持總樹數 32。若無法整除，多出的樹依輸入順序分配給前面的視窗。
- 每個子森林先用自己的樣本數正規化；再依子森林樹數比例做**異常分數的算術平均**。不共用正規化常數，也不先平均不同尺度的原始深度。
- 原始森林的分數本身是各樹深度平均後做指數轉換，因此這裡是子森林分數的加權平均，不等同把所有樹分數直接做算術平均。
- `--window` 保持單一視窗行為；不開啟 `--windows` 時不改原演算法與亂數消耗。深度與切割方式仍可獨立控制，以便消融。
- 相同樹數不表示相同成本：兩個子森林會保留兩份視窗並增加調度成本；本設定最多保留 2048+4096=6144 筆向量，比單視窗 2048 多，應另外評估記憶體與時間。

Python API：

```python
from OnlineIForest import OnlineIForest

model = OnlineIForest.create(
    'multiwindowonlineiforest', window_sizes=[2048, 4096], num_trees=32,
    max_leaf_samples=32, depth_limit='code', n_jobs=1,
)
model.learn_batch(batch)
scores = model.score_batch(batch)
```

評估維持專案既有的 **learn → score** 批次流程，便於與上傳結果比較。新方法本身不讀取標籤；但先學習目前批次再評分，並非嚴格的先預測再學習（prequential）測試，不能把這些結果當成部署前未知樣本的性能保證。

`python -m unittest discover -s tests -v` 包含五項檢查：單視窗與原模型逐分數和亂數狀態相同、固定樹數與權重、獨立視窗遺忘、超大批次及非法參數，以及 CLI 的設定／NPZ 輸出與互斥參數。

## 4. 本次實驗結果

原作者五個資料集已從固定上游 commit 下載，並以 Git LFS 指標中的大小與 SHA-256 核對。這次跑完 Annthyroid 多視窗 30 次、INSECTS 多視窗 5 次；另重跑 Annthyroid 原版與論文深度、INSECTS 原版各 seed 0 作回歸核對，與上傳 NPZ 的標籤逐項相同，AUC 相同，分數最大絕對差異均約 5.6×10⁻¹⁷。

| 比較 | 基準中位數 AUC | 多視窗中位數 AUC | 多視窗贏／輸 | n | 雙側 p（未校正） |
|---|---:|---:|---:|---:|---:|
| Annthyroid 原版 2048 → 多視窗 | 0.672091 | 0.678269 | 20／10 | 30 | 0.016431 |
| Annthyroid 論文深度 → 多視窗 | 0.745782 | 0.678269 | 4／26 | 30 | 0.00001061 |
| INSECTS 原版 2048 → 多視窗 | 0.778932 | 0.788099 | 5／0 | 5 | 0.062500 |
| INSECTS 單視窗 4096 → 多視窗 | 0.810056 | 0.788099 | 1／4 | 5 | 0.125000 |

所有方法總樹數皆為 32；多視窗不另外加深樹。這些數據仍使用已看過的資料流與原先種子（Annthyroid 0–29、INSECTS 0–4），不是獨立的保留測試。五對非零差異的雙側精確 Wilcoxon 最小 p 就是 0.0625，因此即使五次全勝，也不能按 0.05 門檻宣稱顯著。表中的小樣本 p 直接用 SciPy 計算；既有 `compare.py` 在少於六對時會選擇不輸出檢定。

INSECTS 的 208 個寬度 5000、步長 1000 的滑動視窗：

| 方法 | 時間軸上視窗中位數的平均 | 最低視窗中位數 |
|---|---:|---:|
| 2048，32 棵樹 | 0.817849 | 0.553071 |
| 4096，32 棵樹 | 0.822819 | 0.667052 |
| 2048+4096，各 16 棵樹 | 0.816593 | 0.636324 |

多視窗的最低視窗中位數高於原版，但平均視窗 AUC 略降；單一 4096 視窗在這兩項指標皆較高。本次沒有另跑長時間的 Mammography、Satellite、Shuttle 多視窗基準，亦未測量峰值記憶體，所以不能推論多視窗適合所有資料集或更省資源。

**判斷：保留多視窗作可選實驗方法，不取代原預設。** Annthyroid 現有的論文深度仍比這個新方法好；INSECTS 則以既有單視窗 4096 最值得後續驗證。下一步應先固定設定，再到未參與選擇的資料流、種子與先評分再學習的流程驗證，避免繼續在這組測試結果上調參。
